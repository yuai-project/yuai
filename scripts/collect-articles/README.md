# 記事候補の収集（#107）

記事候補を検索し、AI に下読みさせて、判定用スプレッドシート（#100）に追記する。

- 「レビュー」タブ: 監修者が判定するタブ。AI が「使える」「要確認」としたものだけが入る。AI の判定は「AIの下書きメモ」列に書く
- 「収集候補」タブ: 集めた候補の全件の台帳。除外候補・無関係も含め、タグの全軸や取得状況まで残す。重複判定に使うので、**どちらのタブも行を消さない**
承認された記事を `articles.json` に反映する部分は、ここでは扱わない。

```
検索（Exa） → 除外ドメイン・既知の URL を除く → 記事ページを取得 → AI の下読み（Claude Sonnet 5.5、Batches API） → シートに追記
```

## 使い方

```bash
npm run collect:articles -- --limit 2 --skip-review   # 検索だけを試す（先頭2クエリ）
npm run collect:articles -- --json > out.json         # 検索と下読みをして JSON に保存（シートには触らない）
npm run collect:articles -- --write-sheet             # 本番と同じ。シートと突き合わせて追記する
```

- `--from <file.json>` を付けると検索をせず、保存した候補を使う。`--skip-review` も付けると下読みの結果もファイルのものを使う
- 1回の費用の目安は、Exa が約 $0.9、下読みが約 $1.2（188件のとき。Batches API で半額）
- 下読みは Batches API に投げて終わるのを待つので、ふつう数分〜1時間かかる（最長3時間で取り消して止める）

## ファイル

| ファイル | 役割 |
|---|---|
| `index.mjs` | 入口。流れの組み立て |
| `queries.mjs` | タグの軸から検索クエリを組む |
| `search/` | 検索プロバイダ。Tavily に替えるときはここに足す |
| `dedupe.mjs` | 除外ドメインと、既知の URL との重複判定 |
| `fetchPage.mjs` | 記事ページを取得して本文の冒頭を取り出す（保存はしない） |
| `reviewPrompt.mjs` | **AI の下読みの判定基準（仮置き。#108 で詰める）** |
| `review.mjs` | AI の下読みの呼び出しと、ラベル・タグの整え |
| `sheetRow.mjs` | シートの列の定義。「レビュー」は見出しの名前で書く。「収集候補」は列を動かすときシートの見出しも合わせる |
| `sheets.mjs` | スプレッドシートの読み書き |

## 環境変数

`.env.example` を見て `.env.local` に入れる。Actions では Secrets に同じ名前で入れる。

## サービスアカウントの作り方（スプレッドシートの認証）

一度だけやればよい。個人の Google アカウント（gmail.com）で作れる。

1. [Google Cloud Console](https://console.cloud.google.com/) を開き、上部のプロジェクト選択から **新しいプロジェクト** を作る（例: `yorido-collector`）。請求先の登録は要らない
2. **API とサービス → ライブラリ** で「Google Sheets API」を検索し、**有効にする**
3. **IAM と管理 → サービス アカウント → サービス アカウントを作成**
   - 名前は `article-collector` など。ロール（権限）は付けずに **完了**
4. 作ったサービスアカウントを開き、**鍵 → 鍵を追加 → 新しい鍵を作成 → JSON**。JSON ファイルがダウンロードされる
   - 「鍵の作成が組織のポリシーで無効」と出たら、組織のアカウントで作っている。個人のアカウントで作り直す
5. 判定用スプレッドシートを開き、**共有** にサービスアカウントのメールアドレス（`article-collector@<プロジェクトID>.iam.gserviceaccount.com`）を **編集者** で追加する。「通知する」は外してよい
6. `.env.local` に次を入れる
   ```bash
   GOOGLE_SHEET_ID=<スプレッドシートの URL の /d/ と /edit の間の文字列>
   GOOGLE_SERVICE_ACCOUNT_KEY=<下のコマンドの出力>
   ```
   ```bash
   base64 -i ~/Downloads/<ダウンロードした鍵>.json | tr -d '\n'
   ```
7. **ダウンロードした鍵の JSON は消す。** リポジトリの中に置かない・コミットしない。なくしたら手順 4 で作り直し、古い鍵は削除する

鍵を持っていると、そのシートを編集できる。共有するのはこのシートだけにして、ほかのファイルには追加しない。
