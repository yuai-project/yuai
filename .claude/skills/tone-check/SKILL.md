# プロダクト思想チェック

このプロダクトの価値は**文言そのもの**にある。機能が動くかより優先される。
利用者に見える日本語が増えた・変わったときは、必ずこの検査を通す。

## 検査対象

利用者の画面に出る日本語すべて。

- `src/data/mockAdvice.js` — AI回答の7セクション（**最重要**）
- `src/data/mockStories.js` — 体験談
- `src/config.js` — サービス名・タグライン・コンセプト
- `src/pages/*.jsx` / `src/components/*.jsx` — 見出し・説明文・ボタン・プレースホルダ・エラー文言
- LLM に渡すシステムプロンプト（API 接続後）

差分だけを見る場合:

```bash
git diff origin/main... -- src/
```

コード（変数名・コメント）は対象外。**利用者が読む文字列だけ**を見る。

## 7項目

### 1. 相手の心理状態を断定・診断しない

見立ては「かもしれません」「場合があります」で止める。断定形と診断語を使わない。

- NG: `お父さまは承認欲求が満たされていない状態です`
- NG: `これは認知的不協和です` — 診断名を当てる
- OK: `社会や将来への不安、既存の情報やメディアへの不信感を抱えているのかもしれません`

複数の見立てを並べるときは「これはあくまで一つの見立てです」という但し書きを添える。

### 2. 相手を「陰謀論者」とラベリングしない

**人ではなく状況を描写する。** 属性でくくらない。

- NG: `陰謀論者の家族との接し方` / `信者になってしまった相手`
- NG: `ハマっている人は〜する傾向があります` — 人を類型化している
- OK: `その話を信じている相手` / `大切な人が極端な情報に触れているとき`

### 3. 相手を必ず変えられると約束しない

効果を保証しない。「〜すれば解決します」「必ず〜できます」を使わない。

- NG: `この聞き方をすれば、相手は必ず冷静になります`
- OK: `こんな返し方を試してみる` / `かえって会話が続きにくくなることがあります`

見出しレベルでも「試してみる」「かもしれない」の温度を保つ。

### 4. 危険な状況では利用者自身の安全を最優先

「無理に話さなくていい」という**逃げ道を必ず残す**。
対話を続けることを推奨しきらない。会話を終える・距離を取る選択肢を明示する。

- NG: `諦めずに対話を続けましょう`
- OK: `会話を続けることがつらいときは、少し距離を取ることも大切な選択肢です`
- OK: `こんなときは無理に話さなくて大丈夫`

金銭被害・暴力・健康被害が絡む文脈では、専門の相談窓口に繋ぐ導線を削らない。

### 5. 実在の個人・団体・特定の思想を攻撃しない

実名・団体名・特定の主義主張を名指しして否定しない。
体験談の投稿例やモックデータにも実在の固有名詞を入れない。

### 6. トーンは安心感・やさしさ・信頼感

暗い・攻撃的・監視的にしない。

- NG: `相手の言動を記録しておきましょう` — 監視的
- NG: `手遅れになる前に` — 恐怖を煽る
- OK: `まずは、ここまで向き合ってきたご自身をねぎらってあげてください`

利用者を責める言い方（「〜すべきでした」）も避ける。

### 7. 警告は赤黒ではなくやさしい警告色

「できれば避けたい対応」などの警告表示は、危険を煽る配色にしない。
`AdviceCard` の `tone` プロパティを使い、色を直書きしない。
色は `src/index.css` の `@theme` トークンから取る。

## 報告のしかた

見つかった問題を、**該当箇所と書き換え案をセットで**挙げる。

```
src/data/mockAdvice.js:42  項目1（断定）
  現状: 「お母さまは孤独を感じている状態です」
  提案: 「お母さまは孤独を感じているのかもしれません」
  理由: 断定形で相手の心理状態を決めつけている
```

- 該当なしなら「7項目すべて問題なし」と明言する。曖昧に濁さない
- 判断に迷うものは「グレー」として挙げ、**勝手に直さずユーザーに判断を仰ぐ**
- 指摘は文言に対して行う。書いた人を責めない
